# src

[English](README_en.md) | [Русский](README_ru.md)

Этот каталог содержит ядро реализации XER и основные подсистемы рантайма.

## Основные области

- `app/` — оболочка приложения: окна, ноды NodeGraph приложения, crash handler
- `async_io/` — асинхронный I/O, пулы буферов, планирование, аппаратная абстракция
- `audio/` — аудио-движок, DSP, эффекты, хосты VST3/CLAP, virtual audio cable
- `cache/` — утилиты кэширования, персистентность, канал разделяемой памяти
- `cef/` — хост браузера CEF (встраиваемые Chromium-view)
- `content/` — контентные подсистемы: сеть, AI, интеграции моделей
- `flux/` — компоненты терминала и рендеринга рантайма
- `helper/` — утилиты: строки, буферы, span'ы, сырые указатели
- `lsui/` — `lsui.exe` — Lua-скрипты с окнами UI
- `lunca/` — минимальный протокол packet/udp_socket
- `media/` — медиа-конвейер: демуксеры, декодеры, рендереры, приёмники, муксеры, плеер
- `node_graph/` — модель графа, исполнитель, история, проекты на SQLite
- `sql/` — слой персистентности на SQLite (ORM, построитель запросов)
- `ui/` — UI-фреймворк на WinAPI, 80+ виджетов, CSS-движок (`css/`), DevTools, XML UI
- `wrapper/` — мосты к внешним библиотекам: Skia, FFmpeg, CUDA, ANGLE, OpenCV
- `modules/` — JavaScript-модули, экспонированные в рантайм
- `app_command.*` — парсинг командной строки и хелперы точки входа

## Упаковка в YA.*.dll

Статические библиотеки проекта упакованы в общие модули `YA.*.dll` через
`cmake/YaDll.cmake` (экспорты генерирует `cmake/GenYaDef.cmake`).
Исполняемые файлы линкуют YA-DLL; сторонние зависимости встроены в них
статически, поэтому бинарники работают без MinGW/MSYS2-рантайма.

## Высокоуровневые обязанности

- оркестрация рантайма и динамическая компиляция
- нативное исполнение и мосты к JavaScript-окружению
- регистрация модулей и связность рантайма
- низкоуровневый I/O, сеть, буферизация и работа с железом
- обработка аудио и DSP-возможности
- AI- и модель-ориентированные бэкенды с опциональными интеграциями

## Примечания

Проект намеренно модульный. Большинство возможностей живёт в выделенных
подкаталогах, а не в едином монолитном рантайме. Это упрощает развитие
кодовой базы и поддержку опциональных функций и платформенных интеграций.
