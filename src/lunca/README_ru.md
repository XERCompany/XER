# Lunca — высокопроизводительное аудио-стриминг

[English](README_en.md) | [Русский](README_ru.md)

Lunca — высокопроизводительная система аудио-стриминга, построенная на
архитектуре глубоких модулей. Обеспечивает потоковое аудио реального
времени поверх UDP с минимальной задержкой.

## Обзор

Lunca позволяет стримить аудио в реальном времени без стандартных
протоколов вроде HTTP или WebSocket. Используется UDP для максимальной
скорости и эффективности с механизмами надёжности на уровне приложения.

## Ключевые возможности

- **Низкая задержка**: оптимизировано под минимальную задержку стриминга
- **На базе UDP**: UDP для максимальной скорости и эффективности
- **Собственный URI-протокол**: `lunca://<IP>/on/<STREAM_ID>` для управления стримом
- **Кроссплатформенность**: Windows, Linux, macOS
- **Глубокие модули**: маленькие интерфейсы с максимально скрытой сложностью
- **Интеграция с XER**: использует аудио-подсистему XER для абстракции устройств
- **Кодек Opus**: высокоэффективное сжатие аудио
- **Модульность**: чёткое разделение на common, streaming и protocol

## Принципы дизайна

### Стратегия глубоких модулей
- **Маленький интерфейс**: минимальный публичный API (например, у UDPSocket всего 4 базовых метода)
- **Глубокая реализация**: сложная логика скрыта в приватной реализации (паттерн PIMPL)
- **Высокий рычаг**: один вызов интерфейса запускает сложные операции
- **Локальность изменений**: правки содержатся внутри модулей
- **Тестируемость**: чистые швы для моков и тестов

### Разделение модулей
- **common/**: общие утилиты для клиента и сервера
- **streaming/**: захват, кодирование, декодирование, воспроизведение аудио
- **protocol/**: разбор управляющих сообщений и URI
- **server/**: серверная реализация
- **client/**: клиентская реализация

## Спецификация протокола

### Формат URI
```
lunca://<SERVER_IP>/<COMMAND>/<STREAM_ID>
```

Примеры:
- `lunca://192.168.1.100/on/mic0` — запустить стрим
- `lunca://192.168.1.100/off/mic0` — остановить стрим
- `lunca://192.168.1.100/status/mic0` — запросить статус

### Управляющее сообщение (JSON)
```json
{
    "command": "ON|OFF|STATUS",
    "stream_id": "mic0",
    "client_ip_for_audio": "192.168.1.101",
    "client_port_for_audio": "12346",
    "sample_rate": 48000,
    "channels": 2,
    "bitrate": 128000
}
```

### Формат аудио-пакета
```
[Заголовок (8 байт)][Полезная нагрузка]
Заголовок:
  - Stream ID: 4 байта
  - Номер последовательности: 2 байта
  - Метка времени: 2 байта
Полезная нагрузка: закодированные аудиоданные (Opus)
```

## Технологический стек

- **Язык**: C++17 или новее
- **Сеть**: сырые сокеты (WinAPI на Windows, POSIX на Linux/macOS)
- **Аудио**: аудио-подсистема XER для I/O, Opus для кодирования/декодирования
- **Сборка**: CMake

## Примеры использования

### UDP-сокет

```cpp
#include "lunca/common/udp_socket.h"

using namespace Lunca::Common;

// Создать сокет
auto socket = UDPSocket::Create();

// Привязать к адресу
socket->Bind("0.0.0.0", 12345);

// Отправить данные
std::vector<uint8_t> data = {0x01, 0x02, 0x03};
socket->SendTo(data, "192.168.1.100", 12345);

// Принять данные
std::vector<uint8_t> received;
std::string from_addr;
int from_port;
socket->Receive(received, &from_addr, &from_port);
```

### Аудио-пакет

```cpp
#include "lunca/common/packet.h"

using namespace Lunca::Common;

// Создать пакет
AudioPacketHeader header(1, 100, 5000);  // stream_id=1, seq=100, ts=5000мс
AudioPacket packet(header);

// Установить нагрузку
std::vector<uint8_t> encoded_audio = {/* данные Opus */};
packet.SetPayload(encoded_audio);

// Сериализовать
std::vector<uint8_t> serialized = packet.Serialize();

// Десериализовать
AudioPacket received_packet;
received_packet.Deserialize(serialized);
```

## Преимущества глубоких модулей

### Рычаг
- `UDPSocket::Bind()` обрабатывает создание, настройку и привязку сокета
- `AudioPacket::Serialize()` обрабатывает сериализацию заголовка/нагрузки
- Сложные операции — через простые вызовы интерфейса

### Локальность
- Сетевая логика изолирована в common/
- Аудио-логика — в streaming/
- Логика протокола — в protocol/
- Изменения не растекаются по кодовой базе

### Тестируемость
- UDP-сокет мокабелен для интеграционных тестов
- Структуры пакетов тестируются независимо
- Чистые швы для внедрения зависимостей
